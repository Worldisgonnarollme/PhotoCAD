# PhotoCAD: многостраничные чертежи, точки и фотоотчёт

Дата: 2026-09-25  
Ветка: `updates`

## Цель

Сделать PhotoCAD надёжным инструментом для фотофиксации по чертежам: сохранять настройки, импортировать изображения и PDF, привязывать точки к страницам и нормализованным координатам, а также собирать одностраничный фотоотчёт с одной фотографией на листе A4. Существующие объекты, чертежи, точки, фото и пользовательские описания должны пережить обновление.

## Согласованные требования

- Тема: «Системная», «Светлая», «Тёмная», сохраняется между запусками, применяется ко всему Compose UI и системным областям окна. Viewer не устанавливает отдельную глобальную тему.
- Настройки сохранения добавленных фото в галерею и сжатия фото хранятся в существующем DataStore `user_profile` и влияют на поведение. Сжатие применяется к фото, а не к исходным файлам чертежей: создаётся JPEG с ограничением размера и качеством около 85. При включённом сохранении в галерею фото после добавления камеры или picker копируется в медиатеку.
- Импорт чертежей принимает PDF, PNG, JPG и JPEG через системный picker, копирует оригинальные байты во внутреннее хранилище и сохраняет согласованные MIME/расширение. Несколько чертежей в объекте остаются поддержаны.
- Изображение имеет одну страницу. PDF читается через Android `PdfRenderer`; одновременно открыта и растеризуется только выбранная страница.
- Точка принадлежит чертежу и странице; номер страницы хранится с единицы. Координаты `x/y` нормализованы в пространстве страницы, не экрана, поэтому сохраняют положение при масштабировании, панорамировании и изменении размера окна. Новая точка привязана к активной странице, и на экране отображаются точки только активной страницы.
- Сохраняются выбор, перетаскивание, цвет, комментарий, подтверждаемое удаление точки и мини-просмотр. Перемещение преобразует координаты с учётом текущего масштаба/панорамирования и корректно работает в мини-просмотре.
- Фото остаются привязанными к точке. При добавлении фото комментарий точки копируется как исходное индивидуальное описание. Последующее изменение комментария не меняет сохранённые описания фото. Черновые подписи подготовки отчёта сохраняются только по явному действию.
- Фотоотчёт включает все страницы одного чертежа. Каждая фотография занимает отдельную книжную страницу A4, пропорции изображения сохраняются внутри чёрной прямоугольной рамки. Под фото: сквозной номер фото, номер точки, номер страницы чертежа и непустое описание фото (индивидуальное, иначе комментарий точки). Титульного листа и общей информации нет.
- Сохраняются генерация и предпросмотр PDF, системное сохранение, отправка и отмена. Ошибки отсутствующих/повреждённых исходников не меняют исходные данные.
- Добавляется недеструктивная миграция Room с `pageNumber INTEGER NOT NULL DEFAULT 1`. Удаление точки/чертежа/объекта очищает дочерние данные и файлы после транзакции, но общий файл удаляется только при отсутствии других ссылок.
- Не выполнять push, merge, rebase или создание PR.

## Архитектура и потоки данных

### Настройки и тема

`UserPreferences` остаётся единственной точкой доступа к DataStore. Настройки темы и фото получают отдельные ключи; очистка профиля удаляет только ключи профиля. `MainActivity` наблюдает выбранную тему и передаёт схему в корневую тему Compose, одновременно согласуя цвета системных панелей и светлые/тёмные значки. `SettingsScreen` редактирует те же настройки. Вложенная тема `ViewerColors` удаляется; цвета экрана просмотра берутся из корневой схемы.

### Хранилище и чтение чертежей

Импортёр определяет тип по MIME/имени URI с проверкой поддерживаемого набора, копирует в приватное хранилище без перекодирования и присваивает правильное расширение. Существующие потоки создания объекта и добавления чертежа используют общий импортёр.

Новая абстракция чтения чертежа предоставляет число страниц и растеризацию одной страницы по запросу. Изображение реализует страницу 1; PDF открывает `ParcelFileDescriptor`/`PdfRenderer`, открывает один `Page` на время рендеринга и освобождает ресурсы. UI хранит активную страницу (с единицей в модели) и не кеширует полный документ как список Bitmap.

Для координат используется прямоугольник содержимого страницы после вписывания пропорций в область просмотра. Тапы и жесты сначала переводятся обратно через pan/scale, затем — из прямоугольника содержимого в `[0,1] × [0,1]`. Отрисовка выполняет обратное преобразование. Мини-просмотр использует тот же нормализованный формат без трансформации основного viewer.

### Схема и удаление

Room schema 6 добавляет номер страницы точке; `MIGRATION_5_6` заполняет существующие строки значением 1. Запрос отчёта возвращает идентификаторы точки и страницу наряду с фото, индивидуальным описанием и комментарием. Миграционный тест проверяет сохранность старых строк/путей/описаний и значение страницы.

Операции удаления сначала собирают затронутые пути, атомарно удаляют строки БД, затем проверяют ссылки на каждый путь в `drawings.filePath` и `photos.filePath`. Удаляются только неиспользуемые файлы. Профиль/аватар не затрагивается удалением объектов.

### Фотографии и настройки

Операции импорта фото читают предпочтения один раз на операцию. При сжатии входное изображение декодируется с ограничением размеров и кодируется JPEG качества около 85; без сжатия сохраняются оригинальные байты и разумное расширение. Фото добавляется к медиатеке только после успешного сохранения приложения; отмена и ошибки чистят только созданный приложением временный файл и не меняют БД. После успешного добавления `PhotoStore` по-прежнему атомарно фиксирует текущее значение комментария точки как описание фото.

### Отчёт

Строки запроса одного drawing включают фотографии точек со всех страниц и упорядочиваются стабильно по странице, точке и фото. Подготовка отчёта создаёт неизменяемый draft; текстовые правки живут в draft до явного сохранения отдельного описания. Нумерация назначается после фильтра выбранных фото. Генератор рисует один отчётный элемент на одну A4-страницу, масштабирует фото внутрь рамки без обрезки и строит подпись из номера фото, номера точки, страницы чертежа и непустого описания. PDF строится локально по одному изображению за раз; временный файл публикуется только после завершения. Существующие preview/save/share потоки сохраняются.

## Ошибки и сохранность

- Ошибка определения формата, чтения URI, пустой/повреждённый PDF, недоступная страница и повреждённое изображение показываются пользователю, не создавая запись чертежа/фото.
- Picker может быть отменён без побочного эффекта.
- Ошибка/отмена генерации удаляет только временный/частичный отчёт; существующие исходники и Room-записи остаются нетронутыми.
- Миграция добавляет поле с default 1 и не пересоздаёт таблицы с данными.
- Удаление файлов выполняется только после commit и проверки оставшихся ссылок.

- Инструментальный миграционный тест Room подтверждает сохранение прежних записей и page 1.
- Целевые существующие тесты фото/описаний/отчёта/удаления обновляются по необходимости.
- Сборка доступной Gradle-задачей и выполнение релевантных unit-тестов; инструментальные тесты запускаются, если доступен эмулятор/устройство.
